# 测试价值 Review

> 历史审查记录：结论仅覆盖检查时的代码与环境。当前行为见[接口契约](../interface-contract.md)，未修复项见[已知问题](../known-issues.md)。

## 结论

**现有测试包含可复用的行为保障，也包含旧契约和实现细节。312 项不是 312 项当前需求保障。** 本轮不提供“有意义测试占比”：尚未逐条改变实现来验证测试能否发现错误，不能凭标题或通过率计算有效性。

当前最有价值的是预算、继承、分支恢复、取消收尾、真实 IPC 和离线 SDK 组合测试。最需要修改的是与当前契约相反的断言，以及把单函数测试结果扩大解释为完整生命周期保障的测试。

本轮未删除测试，也未修改实现。

## 本轮重跑确认

继续整理架构时，在同一工作区重新运行 `npm test`。环境为 Linux、Node.js `22.23.4`、npm `12.2.1`、Pi SDK `1.4.0`。记录时间为 2026-10-24。

- 命令退出码：`1`。
- TAP 结果：312 项，308 通过、2 失败、2 跳过，无取消。
- 耗时：30.527 秒；仅代表本机本次运行。
- 与此前基线一致，没有新增失败。

两个失败分别为：

1. `disable, re-enable and description changes preserve the original declaration prefix`：`test/responses-tool-prefix.test.mjs:34` 期望 `anchorsAdditions === true`，实际为 `undefined`。
2. `offline SDK: Responses Capability retains its declaration prefix, blocks inherited execution and returns compact interfaces`：`responses-prefix` 场景的同一旧断言先在模拟检索中失败，之后以 `discovery.isError === true` 表现为发现失败。

没有修改断言来让测试转绿。后续应迁移到实际请求声明与执行权限的验收，不直接删除检查。

本轮另有 6 个投递机制输出场景和 12 个含断言的边界实验，位于 `reproductions/`。它们不是当前 `npm test` 的组成部分，也不计入上述 312 项。

## 已确认需要更新的旧契约测试

至少以下 4 个运行用例含有与已确认目标直接相反的断言。更新时应保留其中仍有价值的部分，不按文件整批删除。

| 位置 | 当前保护的行为 | 目标 |
| --- | --- | --- |
| `test/subagent-contract-redesign.test.mjs:75` | 按非 ASCII 字符比例拒绝整个批次 | 删除语言硬拒绝，英文仅为推荐 |
| `test/subagent-contract-redesign.test.mjs:275` | 正常完成和取消不通知 | 宿主自动发完成通知；终态保留状态区别 |
| `test/subagent-runtime.test.mjs:1170` | 仅失败通知，完成时保持静默 | 正常完成也应通知 |
| `test/capability-result.test.mjs:8–30` | Main 返回结果保留远端候选 | 远端候选不进入 Main |

另有待重新判断的实现绑定：

- `test/tool-prompts.test.mjs:93` 和离线 SDK 的 `capability-missing` 场景，保护 Capability 对 Subagent 工具注册的依赖。底层复用 Subagent 已确认，但通过公开工具注册表判断依赖的做法不保留。应改为验证统一装配提供内部执行能力，即使公开 Subagent 工具未注册或未激活，Capability 仍能执行内部检索。

- 路由测试中的固定 provider／模型名称断言，可能只在保护配置。应与选择流程和权限约束分开评估。

## 为何发现了缺陷，测试仍然通过

### Socket 夹具代替产品完成了部分清理

`test/subagent-socket.test.mjs:21–30` 的 teardown 先销毁全部客户端，再关闭 server，最后递归删除目录。

这对测试环境清理是正确做法，但会避开“调用方仍连接时 server 能否退出”的问题。测试成功不证明扩展自身拥有完整的连接回收路径。

`:53–73` 确实检查了显式 `server.close()` 后端点不存在，具有价值。但该测试不经过 Pi 的会话退役链路，也不覆盖跨用户权限。

### 单次 shutdown 不覆盖重复切换

`test-support/subagent-sdk-scenario.mjs:944` 发出一次 shutdown。离线 SDK 包装器使用独立临时目录，退出后又递归移除目录。

这些测试验证不少 SDK 组合行为，却没有验证连续多次激活、退役后，当前服务仍能关闭。它们也不能证明真实运行目录没有残留。

### 解析器测试不覆盖 Shell 选择

`test/shell-preflight.test.mjs` 显式传入解析器路径，主要测试 `src/shell-preflight.mjs`。

Windows 聊天框问题发生在入口选哪一个 Shell。即使 PowerShell 解析器测试通过，`user_bash` 入口仍可能错误地按 Bash 检查。这不是解析器测试无意义，而是产品链路缺了一层测试。

### 正常对象测试不覆盖发送者输入类别

已有测试保护正常消息对象的发送者绑定，却未覆盖 JSON 标量和数组的序列化差异。结果是正常路径正确，异常输入仍可被接收端归为 Main。

纯文本改造后，应验证任意正文都进入宿主构造的同一种信封，包括多行文本和 JSON 字面内容。

### 提示词短语存在不等于模型会使用

`test/tool-prompts.test.mjs:39–60` 检查多条英文短语存在。这能发现文案被误删，却不能证明模型理解调用时机，也不能证明模型会选择 `write`／`msg_write`。

应保留少量工具说明完整性检查，并另外建立固定任务场景评估：记录模型何时调用 Capability、是否使用托管通信、是否错误地用 sleep 等待。模型评估和确定性单测分开报告。

## 测试保留原则

| 类别 | 处理 |
| --- | --- |
| 保护当前目标中的独立不变量 | 保留；改内部架构时继续验证同一行为 |
| 有价值行为使用旧内部接口表达 | 迁移测试，不要求保留旧接口 |
| 断言与当前契约相反 | 改写；不为了全绿保留旧行为 |
| 只重复代码内部字段或固定文案 | 证明价值后保留，否则合并或删除 |
| 随退出交付模块存在的测试 | 随模块和命令一并处理 |
| 隔离环境测试未覆盖用户链路 | 补组合测试，不把局部测试当作端到端证明 |

## 优先补的场景

1. 连续多次会话切换，再正常退出；退出后检查全部自有端点。
2. 客户端保持连接、只发送半个报文时退出。
3. root 先启动、普通用户后启动，以及同会话的不同权限运行。
4. 权限不足、残留 Socket、活跃 Socket 和普通文件占位；拒绝删除不属于当前实例的资源。
5. 异常进程退出后重启，识别并回收自有失效端点；不宣称 SIGKILL 时能执行清理。
6. SDK Session 刚创建时预算耗尽，验证释放。
7. 历史中途写入失败、末尾成功，验证错误仍可见。
8. 正常完成唤醒，以及工具调用期间待投递消息与终态合并。
9. 无审批界面时，远端候选仍不进入 Main。
10. Windows 聊天框入口与实际执行器选择一致。

跨用户测试应放在受控环境内，不修改开发者当前的权限或清理正在使用的端点。本轮没有执行提权、`chown` 或删除现有运行目录。

测试清理的目标是让每个测试回答一个真实风险，不是预设把数量减到多少。
