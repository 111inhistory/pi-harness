# Proposal：Capability 反馈精简与交付筛选

本文已归档。反馈精简、交付筛选与 Codemode 快照边界已实现，当前行为见[接口契约](../interface-contract.md)和[当前架构](../architecture.md#capability)。下文保留实现范围的讨论；SDK allowlist 下的激活记忆不一致仍见[已知问题](../known-issues.md)。

## 范围

Capability 继续搜索当前会话已经注册、非 hidden 且符合权限的本地工具和 Skill。移除工具入口对全部 MCP 后端的等待。尚未注册的服务器本次不可发现；连接完成后可重新搜索。

本轮不加入重连机制，不读取未连接服务器配置作为候选，不增加原生 SDK 控制接口，也不另建连接管理器。连接恢复沿用 Pi 原生行为和用户的 `/mcp reconnect`。

检索排序仅调整 MiniSearch 配置，采用 BM25 `k=0.9`、`b=0.9`、`d=0`。本轮不拆分字段、不增加评分层或模型重排。

## 流程

1. 内部 Agent 并行搜索本地候选。
2. 宿主保留完整候选，只向内部模型返回精简反馈。
3. 内部 Agent 累积选择，最后显式结束。选择期间不提前激活工具或写入父分支。
4. 宿主在交付前重新核对当前注册与权限，剔除失效成员，重算分组数量。
5. 宿主先持久化最终选择，再激活并读取实际激活结果。
6. Main 收到确认后的资源引用与接口入口；新增工具在后续调用中使用。

搜索没有匹配是正常空结果。选中成员全部失效且没有保留 Skill 时返回失败。部分选择失效时返回部分成功，并给出简短原因。成功清单不保留不可用成员的占位项。

## 三处精简

| 位置 | 模型接收的内容 | 宿主保留的内容 |
| --- | --- | --- |
| `capability_step` | ref、名称、短描述、类型、必要路径或工具数量 | 完整成员、接口、排序诊断和共同指引 |
| 最终 Capability 返回 | 已选资源、实际数量、接口入口、Skill 路径及简短失败原因 | 完整诊断与规范分支记录 |
| `ALL_TOOLS` | 工具名和短描述 | `describeTool` 可按需返回的完整接口 |

模型能通过原生声明或当前启用的 Codemode 查询参数时，不在结果中重复 schema；两种入口都不存在时，保留调用所需参数。共同指引由规范记忆提供，避免在结果正文中重复。

本轮采用确定的字段投影，不增加廉价模型摘要调用。不能对序列化 JSON 截头截尾。字段精简不缩小选择整个 namespace 的成员范围。

## 重复命中

去重只作用于同一次内部发现。首次命中返回精简候选；后续命中只返回 `repeatedRefs`。宿主继续保存完整候选，因此内部 Agent 仍可选择之前出现的 ref。

已见过与已选中分开。全部命中都重复时，不解释为没有匹配。新一次 Capability 调用重新读取当前目录，不使用跨会话的已见缓存。

## Codemode 边界

沙箱保留执行开始时的工具快照。目录查询不等待所有 MCP 后端；实际嵌套工具调用仍经过 Pi 原生管线。

如果脚本运行期间才通过 Capability 激活新工具，当前脚本不动态增加函数。新增工具从下一次 Codemode 调用使用，提示词只补充这条规则。

## 验证与现有限制

应分别检查内部 step 的正文、实际发给模型的消息及展示层输出。用户报告的 DeepSeek 截断不能仅凭 UI 渲染确定来源。

离线 SDK 回归应验证大 namespace 的反馈为完整 JSON、重复命中不重复正文、选择仍包含全部成员、实际下一次请求能获得接口和指导。真实提供方是否另行截断，仍需在线验收。

SDK `1.4.0` 在一种严格 `--tools` allowlist 下可能保留 MCP 注册，却静默拒绝激活。返回可按实际激活集剔除成员，但先写入的规范记录可能残留。这是已复现的独立限制；本轮如实记录，不增加激活探针、回滚或 SDK 改动。

配置化与 Subagent 提示词定制继续留在[独立 proposal](harness-configuration-and-prompts.md)，不与本轮 Capability 实现混合。
