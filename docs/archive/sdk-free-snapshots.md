# SDK-free current-instruction snapshots

The former renderer kept section text and historical placement journals. Exact placement under transformed SDK contexts required provenance the published SDK does not expose. The replacement renders current business state through the published `context_with_system` lifecycle and removes placement ownership from Harness.

## Contract

- Canonical Preset, discovery, pruning and permission records remain authoritative. Reopen, rewind and inheritance rebuild current instructions from the selected branch.
- Fixed domain owners append current tool/namespace guidance, Capability memory, Preset instructions and pruning notices at the request tail. Main can have separate Preset and Capability section messages; internal retrieval and BTW compose their known domains together. There is no contributor registry or placement coordinate.
- Native history, tool declarations, schemas, compaction and provider serialization remain SDK-owned. Live requests retain SDK tool-removal events. Inherited read-only sessions retain their existing inert interfaces and blocked execution boundary.
- Current snapshots are request-local. They are not persisted or included in `ctx.getSystemPrompt()`. Existing placement entries remain untouched and are ignored; there is no migration or legacy-placement reader.
- Complete forced prompts and later context replacements retain SDK precedence. They can suppress Harness sections. Exact historical requests and whole-request prefix continuity are deliberately outside this contract.
- Current text is resent. Providers can preserve tail system messages or fold them into the head; offline checks do not establish server cache hits or billing.

## Ownership and cost

Rendering reads the current branch and tool scope and uses operation-local maps and sets. The SDK supplies current descriptions and schemas; Harness does not maintain a second metadata-correction layer or provider encoder. Appending a snapshot copies message references and owns its section map for that request. The number of domain owners is fixed; there is no per-record scan of message positions, durable placement index or retained history cache. Existing SDK history and canonical business facts retain their existing owners.

## Verification and regressions

The installed unmodified SDK is the acceptance dependency. Real SDK tests cover same-run discovery updates, ignored obsolete placement entries, independent plugin sections and Preset restoration into internal retrieval and BTW. The existing Capability history PBT retains its original operations and independent business-state model and adds transformed-view and Preset operations. It checks current instructions, caller-body preservation, forced precedence, authority, active declarations and reopen. Native and Parent PBT families remain unchanged.

A native-model counterexample exposed the old live `additiveToolTranscript` optimization removing SDK tool-removal events: disabling `history_alpha`, compacting, then resetting it left an inactive tool declared. Removing that live optimization restores native current-declaration behavior; the original strict oracle remains. Exact replay: seed `-257426390`, path `46:3:2:4:3:4:4:4:5:5:5:5:6:6:6`, command path `5:B`.

A manual-tool SDK fixture assumed the final request message was a tool result. A tail system snapshot made that mock repeatedly issue the same call. The fixture now compares the latest tool-result and user boundaries. Permission and backend assertions remain intact; deadlines are unchanged.

Obsolete journal parser, anchor, replay and prefix-only tests are removed with their mechanisms. Strict canonical business-record validation and distinct authority, privacy, SDK loadout and lifecycle coverage remain. Generated current-state coverage replaces redundant pure projection cases.
