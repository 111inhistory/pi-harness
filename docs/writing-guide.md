# 文档写作约定

## 适用范围

本约定用于项目说明、工具说明、接口契约、设计文档与代码注释。语言规则采用 `hai-simplified-technical` 的简化技术中文规则；代码注释使用英文，具体要求见 [Code comments](#code-comments)。

本约定适用于新增和改写的当前文档。历史正文保留记录时的语境；重用其中内容前应核对代码与当前契约。

## 语言

- 仓库文档正文、标题、表格说明和设计要求统一使用中文。协议名称、代码标识、命令及需要原样保留的日志或报错使用原文。
- 用户界面、命令帮助、补全说明、状态栏和通知统一使用英文，暂不引入 i18n 或语言切换机制。用户输入、外部工具输出与模型返回正文保留原文。

- 同一个概念应使用同一个名称。
- 每句话应只表达一个主题。
- 主语变化时，应写明执行者。
- 代词可能指向多个对象时，应重复对象名称。
- 描述动作时，应直接使用动词，不写“进行检查”一类包装句式。
- 描述条件时，应写明触发条件，不用“适当”“基本上”代替条件。
- 每段应先写结论，再写原因或例外。
- 文件名、工具名、参数名和代码标识符应使用反引号。
- 中文正文应使用中文标点，中文与英文、数字之间应加空格。
- 改写时应保留条件、例外、风险和不确定性。

要求应使用固定词语：

| 用词 | 含义 |
| --- | --- |
| 应／不应 | 要求／禁止 |
| 宜／不宜 | 推荐／不推荐 |
| 可／不必 | 允许／不要求 |
| 能／不能 | 能力或可能性，不表示要求 |

## 事实与设计

- 项目目标应来自作者确认，不应从代码反推。
- 当前行为应注明依据和验证范围。
- 已报告但未复现的 Bug 应注明来源，不应编写根因。
- 设计提案应与当前行为分节，不应把提案写成已实现行为。
- 测试通过不能替代真实模型或平台验证。
- 删除旧文档前，应保留其中尚未核对的约束和例外。

## 代码注释

代码注释使用英文编写，用于解释非显而易见的原因、调用方契约、顺序约束、所有权边界或实际限制。若直接的命名或更简洁的代码已能传达相同信息，优先采用代码本身而非注释。直观的赋值、包装器或私有辅助函数无需文字复述或强制 JSDoc。

对于导出 API 或重要模块，注释应说明调用方无法从类型签名中获知的信息：副作用、生命周期、可变性、错误或部分结果行为以及相关边界。模块级注释保持简短；更宏观的设计归当前契约与架构文档管理。

注释应保持客观与局部性：

- 明确说明被修改的对象及其所有者。数组追加不代表消息正文可变；新建数组不代表内部值已完成深层隔离。
- 明确说明销毁操作实际移除的内容以及仍可能存活的对象。抑制回调不等于摘除观察者，释放包装器不等于底层资源已退出。
- 复杂度与性能表述须限定输入与范围。避免未经实测的“常数开销”“可忽略分配”或“保证响应速度”等说法。
- 当权宜方案依赖上游行为时，引用已测试的依赖版本或具体的源码/契约位置，并说明触发该权宜方案的原因；不要把上游实现代码粘贴进注释。
- 推测性成因与排查历史留在既有审查记录中。不要在注释中仅以“出于安全需要”代替实际依据。

当行为发生变化时，同步检查受影响调用方、实现与测试中的注释，在同一改动中更新或删除过时的名称、格式支持、优先级规则与保证。不要在生产代码中留下变更日志式叙述、被注释掉的旧代码或已退役的兼容说明。TODO 应指向具体遗留条件或问题，不要添加“后续优化”之类空泛要求。

例如，当只有容器和头部需要隔离时，应写 `// Own the append array and session header; historical message bodies stay shared.`，而不是 `// Deep-copy everything so callers can never mutate state.`。同理，只有当原生监听器与 Runtime 观察者确实都已摘除时，才在注释中同时说明二者。注释随代码一起审阅，不设定注释数量或 JSDoc 覆盖率指标。

## 工具提示词

工具提示词的读者是 Agent，不是仓库维护者。工具提示词应给出调用所需的信息，不应要求 Agent 先读仓库设计文档。

工具说明应区分用途、输入、返回值和后续动作。涉及异步执行时，工具说明应区分调用返回、消息送达和任务结束。

改写工具提示词时，应检查 Agent 实际看到的文本。仓库文档、工具注册代码和运行时提示词不应视为同一份内容。

## 术语

| 名称 | 含义 |
| --- | --- |
| Agent | 执行当前任务的模型代理 |
| Subagent | 接受委派任务的子 Agent；代码标识符仍用原名 |
| Tool | Agent 能调用的工具 |
| MCP | Model Context Protocol；本项目按需搜索的工具来源之一 |
| Skill | Agent 按需读取的指导资源，不限于操作教程 |
| Capability | 项目中承担按需搜索的功能；工具名为 `capability` |
| 工具提示词 | Agent 可见的工具用途、参数说明和调用规则 |
| Shell Preflight | Shell 命令执行前的语法检查附加功能 |

状态名、字段名和工具参数以当前接口契约与代码为准。新增术语应在对应文档中说明。
