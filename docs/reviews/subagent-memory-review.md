# Subagent 插件内存收敛

本文记录存储适配与内存收敛阶段。后续真实历史转换见[批量迁移](subagent-migration-batch.md)，最新默认回归与提示词状态见[正文外置记录](prompt-extraction-review.md)。下述“不处理真实会话文件”是该阶段的边界，不代表后续未执行迁移。

## 边界

保持同进程 Pi SDK 执行。不增加外部编排服务、独立模型循环、会话数据库或自制历史加载器。不修改 Pi 包，不处理用户真实会话文件。

Pi 1.4.0 的 SessionManager 分块读取文件，但保留全部解析条目。压缩减少模型输入，不移除旧条目。这部分不在本轮修改范围内。

## 本轮修改

| 插件持有的数据 | 处理 |
| --- | --- |
| 根会话中的全量注册表快照 | 改为 Job 注册、开始、结束与身份字段补丁。普通消息不重写状态 |
| 持久化模型定义 | 只写 provider/id，不写模型 headers、提供方回调或运行时对象图 |
| 持久化继承种子 | 注册时写入原生子文件。Job 只保留文件与起点，不保留 entries |
| 纯内存继承种子 | 每个 actor 隔离复制一次。建立原生 manager 后移交数组，删除 Job 中的种子引用 |
| 已结束的持久化子会话 | 完成 SDK 清理和视图写入后，解除 descriptor 对 manager 的引用。续跑时重开原生文件 |
| 历史读取缓存 | 不跨操作缓存完整 manager。已有 live manager 时复用它 |
| 种子和视图的 JSONL 写入 | 每次序列化一条记录，不再 map + join 整份历史。失败时删除临时文件 |
| 每轮可读历史 | 从原生区间生成独立 Job 视图。缺失时重建，不把视图当恢复来源 |

身份补丁保留未修改字段。Job 结束事件推进 actor 的原生锚点。Fork 首次写入执行写时复制；回退后复用已经生成的自有树，不覆盖父文件。

## 不能清掉的数据

- Main 的原生 SessionManager。宿主 Pi 仍使用它。
- 运行中子会话的原生上下文、执行回调、队列和工具资源。
- 纯内存 actor 的唯一 manager。没有可恢复文件时，不能为了回收内存偷偷落盘或直接丢历史。
- 续跑所需的身份、路径、锚点、任务和结果元数据。
- 原生不透明签名、工具调用配对及有效压缩条目。不能把删除这些数据当内存优化。

本轮不承诺总进程内存有固定上限。原生历史、必要元数据、提供方和其他扩展仍可能持有数据。

## 实测

### 原生 SDK 小样

环境：Node.js 22.23.4、Pi SDK 1.4.0。合成文本 8 MiB，不调用模型。

| 阶段 | GC 后 heapUsed，MiB |
| --- | ---: |
| 模块加载后 | 30.27 |
| 原生 manager 保存文本 | 38.40 |
| 另取两个浅数组 | 38.42 |
| 再深拷贝三份 | 62.54 |
| 释放深拷贝 | 38.42 |
| 创建原生 AgentSession | 38.88 |
| dispose，但继续持有 manager | 38.71 |
| 解除所有会话持有引用 | 30.67 |

`getEntries()`、索引和投影不等于各复制一份正文。主要可省项是深拷贝和长期持有。RSS 在最后仍约为 163 MiB；分配器保留内存页不等于 JS 对象仍存活。

脚本及原始数值：`reproductions/native-session-memory.mjs`、`reproductions/native-session-memory.json`。

### 插件所有权测试

`test-support/subagent-sdk-scenario.mjs` 新增两个隔离场景：

- `memory-owners`：真实 SDK 子会话结束后，通过 WeakRef 和 GC 确认原生 manager 可回收；删除视图后能够重建；续跑重开文件，不重新路由。
- `memory-only`：显式续跑仍包含原任务，不创建 subagent 会话文件。

测试提供方原先保存了整个请求 options，其中的 `onProviderStreamEvent` 闭包持有原生 manager。堆快照确认了这条路径。GC 场景先释放这些测试记录，再检查插件所有权；不删除生产中的执行回调。临时堆快照已删除。

## 验证与未完成项

已通过：

- Runtime、存储与公开契约测试：70 项。Runtime 的 43 项旧用例已迁移，另新增 2 项回归。
- 模型定义不进入持久化元数据；视图失败不压掉终态通知；错误恢复不在验证前追加事件；原生文件使用 actor 的 cwd。
- 真实 SDK 的继承、续跑、取消、失败、重载、GC 所有权和纯内存场景。
- TypeScript 检查。
- 撤回合并需求后，`npm run check` 通过：304 项，302 通过、0 失败、2 项环境跳过。跳过项为 PowerShell 和 Windows 场景，本轮未新增跳过。

这些 SDK 场景使用模拟提供方，不发送模型请求。默认离线套件通过，不等于真实提供方、Windows 实机或完整用户验收通过。

旧 Runtime 测试已迁移到事件折叠、Job 记录和原生区间，不添加旧接口兼容层。取消、预算和续跑断言保留。

两个正向 steer 测试原先把单向 Socket 写完当成宿主已经接收，终态可能先到。测试现用真实接收闸门固定顺序。父会话视图的 content 改为内容块后，断言按块读取，不再当字符串。

### 已收口：撤回消息合并

接入检查点曾有 316 项测试，313 通过、1 失败、2 项环境跳过。唯一失败是 `upstream-main-clear`：进度入队后被清除，协调器把后来的终态合并进已经消失的槽。

作者随后确认：消息合并只是附加功能，暂不实现。Main 和子 Agent 均改为逐条原生投递，而不只为 Main 添加例外开关。

- `sendDelivery` 每次构造一个独立 payload，只做来源、轮次、终态标记和一次原生交接。
- 删除合并槽、批次缓存、队列观察、输入与沉降清理钩子，以及 `message_end` 替换。
- 保留会话代次校验、SDK 遗留队列逐条交接、停止和空闲续跑。不新增重试或永久收件箱。
- 合并专属测试随功能移除，改为独立消息不互改、失败不重试、原生队列保留类型等断言，因此测试总数变化不是跳过失败用例。
- 原失败的清队列场景继续保留并通过。另增加主动清除已入队终态的场景，确认不会重发。

Pi 的队列观察接口没有变化。本轮通过撤回合并要求消除对该接口的依赖，没有改 Pi 或引入外部编排。
