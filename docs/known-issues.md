# 已知问题与验收边界

本页不是完整缺陷清单。类型检查、局部 SDK 场景和历史样本通过，不代表全部边界正确。公开行为见[接口契约](interface-contract.md)，实际所有权见[当前架构](architecture.md)。

## 本机 Socket 的信任范围

本项目信任同用户本机进程，不把同用户恶意程序作为隔离对象，不新增 Socket 认证协议。

报文缺少或误填 `from` 时拒收，不默认冒充 Main。宿主工具绑定实际调用方，也拒绝非受管 Socket／Named Pipe，不能借文件写入连接任意服务。

Socket 请求等待接收处理结果，成功正常返回，失败返回错误。超时或断连可能发生在消息接收之后，不自动重发，也不把正常返回当作模型已读。

## 退役、导航与故障恢复

- 正常切换在 SDK BEFORE 钩子内停止 Job 并保存终态；根上下文移动后禁止旧回调通过 `pi.appendEntry` 写入新分支。
- 写盘失败会锁存并阻止切换被报告为成功。退役超时不释放仍被使用的原生文件，资源保持隔离。
- Shutdown 不可取消。强制退出、超时或原生清理失败仍可能只留下原生对话、没有根终态，下一次需要按中断恢复；没有跨文件事务保证。
- 导航尝试会先停止子 Job。若后续插件取消导航，已经发生的停止不撤销，不自动重跑原任务。
- 不支持多个进程同时写同一根会话；IPC 端点排他不是会话文件锁。

真实 SDK 回归覆盖了正常退役写入一次终态，以及终态落盘失败时取消切换。该覆盖不等于所有插件组合、进程终止点或长期竞态都已验收。

## 原生消息与成本

普通消息和终态不维护合并槽。清除已有原生进度消息不吞没后来产生的终态；用户主动清除终态后不重发。

子会话收尾仍用 `takeQueuedMessages` 读取 SDK 选中的待处理队列；该辅助函数临时切换队列模式并使用探针。它服务于原生输入的保留，不是已经删除的消息合并观察器，不能笼统声称“没有队列探针”。

D2 沿用原生 steer 和空闲唤醒。普通消息可触发 Main 执行；多个子节点先后结束，也可能分别触发父节点的 continuation Job 和新 Budget。本项目不做跨事件成本合并。

## Socket 资源与平台验证

`src/ipc/endpoint.ts` 使用按系统用户隔离的私有目录、属主与 inode 校验、原子硬链接发布、活跃端点保护和自有资源清理。不能通过放宽权限共享端点。

监听覆盖当前注册表，不再随列表显示窗口关闭旧 Actor。累计 Actor 较多时，监听占用也会增长。Windows Named Pipe 的成功、错误和超时响应已验证；资源耗尽、长期运行与多用户切换仍需验证。

## Windows 聊天框命令选错 Shell

已修复。Windows 的聊天框 `!`／`!!` 命令用 PowerShell AST 检查，通过后交给 SDK 原生 PowerShell operations 执行，不再回退到 Bash。Agent 工具调用仍按 `bash`／`powershell` 分别检查。

Windows 11 虚拟机已验证中文命令、检查阶段不执行命令，以及非法语法阻断。实际装配、Named Pipe 成功与错误响应也已验证；完整 Windows 套件仍存在平台断言和未完成场景，不宣称全仓 Windows 回归通过。

## 部分实现仍是 JavaScript

Subagent 应用入口、Runtime、SDK 执行器、会话工厂、身份保留、消息工具和 IPC 运行逻辑已进入严格 TS。旧入口仅重导出这些实现。

存储引擎、路由实现、视图渲染、Budget 状态计算、继承捕获及部分 Capability 代码仍为 MJS。本轮没有把它们整体迁移；它们不会因为 TS 调用方存在就自动获得类型保证。SDK 私有 ModelRuntime 桥也是明确的兼容边界，升级时需要复核。

## Capability 与压缩

- 内部搜索 schema、说明和执行只允许 `local`。远端搜索未启用，候选不返回 Main；审批对象、界面和批准后的流程未实现。
- 工具资格按用户决定只增不减，角色排除仍优先。目录资格视图按同步操作重建，不跨工具调用缓存。
- 只有资源、没有工具的 MCP 服务器仍无独立发现项。
- 分支上的 `capability-discovery` 记录用于恢复已选能力。其前提是自定义记录仍在当前分支；不能概括为任意压缩都不会丢能力。
- 外部 `pi-better-compaction` 的已观察缺陷及兼容逻辑见[压缩调查](reviews/native-compaction-review.md)。本轮未删除这些兼容代码，未改全局插件设置，也未修改 Pi 本身。停用插件后的删减范围仍需独立核实。

## 提示词与模型行为

正文已在 `prompts/`，权限、参数类型和状态裁定不由正文执行。任务语言没有硬拒绝，英文仍是现有路由器的使用推荐。

正文在模块初始化时读取，修改后应重启 Pi；`/reload` 不保证刷新全部 ESM 依赖。文字或 schema 回归不能证明模型多轮遵循情况，角色选择质量与成本仍需实际评估。

## 历史迁移与在线验证

存储 v2 不恢复 v1 检查点。批量转换、两份新对话、原件与约 4.2 GB 备份见[迁移记录](reviews/subagent-migration-batch.md)。原件刻意保留，迁移工具按用户决定暂不清理。

迁移阶段的单样本真实 Gemini 续跑和随后 `GEMINI_SMOKE_OK` 冒烟均成功。本次 TS 接线主要使用新进程里的真实 SDK 与本地模拟模型验证，不能用此前在线结果冒充新实现的在线验收。未因独立 SDK 临时代理问题修改 OAuth 插件、凭据或常驻配置。

Linux 长时间压力测试曾因提供方终止未完成。当前仍缺少完整长压测、多用户、完整 Windows 场景与新 TS 调用链的多轮真实提供方验收。

## 用户查看入口

`subagent_list` 是模型接口，不能替代用户查看、停止和发送消息的界面。用户入口仍未设计交付，远端审批界面也不在本轮范围。
