# 已知问题与验收边界

本页列出未实现功能、待验收场景和现有限制，不是完整缺陷清单。已修复问题与已完成记录见[归档](archive/resolved-issues.md)。公开行为见[接口契约](interface-contract.md)，模块职责见[当前架构](architecture.md)。

## 未实现功能

### 用户查看与控制入口

`subagent_list` 是模型接口，不能替代用户查看、停止和发送消息的界面。用户入口仍未设计交付。

### Capability 远端审批

远端搜索的审批对象、界面和批准后的流程未实现。当前内部搜索 schema、说明和执行只允许 `local`；审批接收方未实现前，不搜索远端，不把远端候选返回 Main，也不自动安装或加载候选。

### 仅提供资源的 MCP 服务器发现

只有资源、没有工具的 MCP 服务器仍无独立发现项。

Inherited 的基础工具注册、延迟 MCP 后端调用与 Responses 原生 `additional_tools` 声明链已在离线 SDK 场景中验证（见[归档](archive/resolved-issues.md#inherited-工具注册与-responses-additional_tools-基础链条)）。

- [ ] 验证父会话动态激活工具后，Inherited 分支在真实提供方在线环境下多轮续跑能实际调用这些工具。
- [ ] 验证原生压缩后的工具继承调用生命周期；不只验证声明仍在离线测试请求中。

当前可用路径继续使用，专项适配另行完成，不以恢复已移除的压缩插件为前提。

- **新 TS 调用链的多轮在线运行**：本次接线主要通过新进程里的真实 SDK 与本地模拟模型验证。此前 Gemini 迁移样本和在线冒烟不能替代新调用链的真实提供方验收。
- **Linux 长时间压力测试**：此前测试因提供方终止而未完成。
- **完整 Windows 套件**：Shell Preflight、Named Pipe 成功／错误／超时响应已有局部验证；完整套件仍有平台断言和未完成场景。
- **资源与用户边界**：监听资源耗尽、长期运行和多用户切换仍需验证。
- **恢复与插件组合**：正常退役和落盘失败已有真实 SDK 回归，但强制终止点、插件取消导航及长期竞态未全部验收。
- **模型行为、角色选择与成本**：提示词和 schema 回归不能证明模型多轮遵循情况，角色选择质量与成本仍需实际评估。

## 剩余技术债

`src/` 与 `extensions/` 生产代码已全部迁移至严格 TypeScript（`storage.ts`、`view.ts`、`routing.ts`、`job-budget.ts`、`pi-job-budget.ts` 集中在 `src/subagent/`，`inherited-context.ts`、`prompt-text.ts`、`skills.ts`、`shell-preflight.ts` 补齐严格类型与单一事实源）。`scripts/` 与历史测试用例（`test/*.test.mjs`）仍保持 MJS。

SDK 私有 ModelRuntime 桥仍是依赖边界，升级时需要复核。子会话收尾仍用 `takeQueuedMessages` 读取 SDK 选中的待处理队列；该辅助函数临时切换队列模式并使用探针，服务于原生输入保留，不能声称已移除全部队列探针。

### SDK allowlist 与 MCP 激活记录

Pi SDK `1.4.0` 在一种严格工具 allowlist 下会保留 MCP 注册，却拒绝激活：例如只列出 `read`、`write`、`capability`，既不匹配目标 `mcp__*` 名称，也不保留隐藏的 `tool_search`。SDK 没有公开的激活资格预检接口，`setActiveTools` 会静默省略成员。

Capability 在激活后读取实际状态，返回失败或部分成功并剔除这些成员；先写入的分支选择记录仍可能包含它们。激活调用抛出异常时也可能留下同类记录差异。这是已复现、未修复的不一致。记录不授予执行权限，但请求记忆可能提示一个未启用工具。恢复办法是让 allowlist 显式匹配所需 MCP 工具，或使用保留默认工具的配置后重新发现。

修复这一边界需要 SDK 公开激活资格，或改变“先持久化、再激活”的记录协议。本轮不增加激活探针、回滚或补偿状态机。

## 现有限制

以下是当前行为边界，不自动列为新增功能待办：

- **故障恢复**：Shutdown 不可取消。强制退出、超时或原生清理失败可能只留下原生对话、没有根终态；下一次需按中断恢复，没有跨文件事务保证。
- **导航取消**：导航尝试会先停止子 Job。后续插件若取消导航，已发生的停止不撤销，不自动重跑原任务。
- **并发写入**：不支持多个进程同时写同一根会话；IPC 端点排他不是会话文件锁。
- **消息成本**：普通消息走原生 steer 或显式续跑，可以触发 Main 执行。子节点先后结束会在父 Subagent 的同一 Job 内继续处理通知，共用原 Budget；等待期间暂停活跃时间计费，总存活租约继续。通知可能触发多次模型请求，本项目不合并不同事件。
- **能力恢复**：工具资格按用户决定只增不减，角色排除仍优先。资格视图按同步操作重建，不跨工具调用缓存。`capability-discovery` 恢复依赖自定义记录仍在当前分支，不能承诺任意压缩都不丢能力。
- **MCP 发现与连接**：Capability 只搜索本会话已注册的工具，不等待全部后端，也不主动重连。工具已经注册和启用，不等于外部服务持续在线；连接恢复沿用 Pi 原生行为及用户的 `/mcp reconnect`。真实提供方是否截断内部 step 反馈仍需在线核对，离线 SDK 回归只验证模型请求中的反馈完整性和大小。
- **提示词刷新**：正文在模块初始化时读取，修改后应重启 Pi；`/reload` 不保证刷新全部 ESM 依赖。
